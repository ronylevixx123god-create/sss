# Astro command catalog

Code baseline: `a75b753b67b2a01125d3c12cf85c6a72c3270364` on destination `integration`. Generated/reviewed 2026-10-19.

This is the full **identified custom-source command inventory**, not a claim that every command is currently usable. It includes plugin.yml entries, framework commands, Arkkit patches, faction subcommands and reviewed listener overrides. Minecraft defaults and commands supplied only by external/bundled plugins (including FactionsKore) are not exhaustively documented here. Configuration-generated warp shortcuts also depend on the actual server files.

**Read the status:** Source wired means registration code exists, not that the plugin enables successfully. Patch means the Arkkit patch must be injected. Unwired, Empty and Dormant entries are not working commands merely because their names exist. Faction/config routes depend on configured features and roles. Rewrites can be intercepted by other plugins.

Permissions listed in the CSV/JSON are checks observed in the handler/class; some apply only to admin subcommands. They are not a complete effective LuckPerms/OP authorization matrix. A missing annotation is not proof that an arbitrary player can safely execute a command.

Latest isolated runtime evidence (see COMMAND-FIXES.md): giftcard alias registration and console rejection passed; Core was disabled, collectors were blocked by dependencies, and the server still logged 109 startup error lines. Most commands below have not had player gameplay tests. Source behavior review is not original-gameplay parity verification.

Inventory: **553 source entries**, covering **538 distinct primary invocation strings**. Aliases and alternate implementations mean these are not counts of independently available live commands. The 194 YAML entries include six multiword EnchantmentAPI labels, which are subcommands rather than separate roots.

## Important differences and collisions

- `/randomtp` selects an online player for staff teleportation; `/wild`/`/wilderness` selects wilderness coordinates.
- `/collectload` runs the same purge-and-save executor as `/collectsave`; it does not load data.
- `/giveall` distributes the held item; its YAML description incorrectly calls it an auto-giveall claim.
- `/titleset` checks OP in code; its description says console-only, which is not an enforced sender restriction.
- `/jackpot`, `/mkit`, `/vkit`, `/lpfix` and several other names have no active registration here. Do not treat their declarations as working features.
- Legacy Slotbot and AstroSlotBot both own `/slot`/`/bot`; WildPvP alternatives share the same plugin name. The runner intentionally stages one of duplicate-name alternatives.
- `/collect` can mean stored collection or the boss-reward alias. `/creload` can mean collector reload or Core broadcast reload. `/envoy` has a new framework handler and a legacy unbound declaration. Runtime command ownership depends on registration/load order.
- `/customblocks`/`/customblock` are forcibly rewritten to `/cblocks view` by Core, discarding arguments; `/cblocks` is claimed by two block systems. These remaining collisions need separate runtime verification; exact lootbox matching and argument preservation were repaired in ARKKIT-ALIAS-FIXES.md.
- `/removeskin` is not verified safe cosmetic cleanup: the handler attempts `setType(null)` on the held item.
- `/cwc item` and `/cwc summoner` grant items; no explicit permission annotation/handler guard appears in that command class. Effective access is not tested.

## Validation and limits

Validated that every one of the 194 descriptor entries and each non-commented Java/Kotlin command/root annotation has a catalog entry, that all source anchors exist, and that CSV/JSON row counts agree. Registration/class wiring and unusual handlers were inspected; annotations alone were not treated as proof of activation.
